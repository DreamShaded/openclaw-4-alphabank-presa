# 04 — SKILL.md: инструкция агенту

`SKILL.md` — это файл, по которому агент решает **когда** активировать скилл и **как** провести
сценарий: какие задать вопросы, в каком порядке звать MCP-инструменты, как защититься от ошибок.
Лежит в `.claude/skills/<name>/SKILL.md` (или `workspace/skills/<name>/SKILL.md`).

Сам по себе кода не исполняет — это структурированный промпт. Но именно он превращает «набор
MCP-инструментов» в осмысленный диалоговый сценарий.

## Frontmatter

Шапка `task-scheduler/SKILL.md`:

```yaml
---
name: task-scheduler
description: "Распланировать задачу до дедлайна: разбить на подзадачи, посмотреть
  загруженность по календарю, расставить блоки в свободные слоты ... и (по подтверждению)
  создать события в Google Calendar."
user-invocable: true
when_to_use: "Когда пользователь говорит 'распланируй', 'распиши на неделю',
  'разбей по календарю', 'успеть к пятнице'."
category: utilities
keywords: [planning, calendar, scheduling, deadline, breakdown, subtasks, google-calendar]
argument-hint: "<описание задачи> [--deadline YYYY-MM-DD] [--category work|personal] [--mode even|blocks]"
license: MIT
metadata:
  author: openclaw
  version: "0.1.0"
---
```

Назначение полей:

| Поле | Зачем |
|------|-------|
| `name` | идентификатор скилла |
| `description` | по нему агент понимает, **что** скилл делает (видно в каталоге скиллов) |
| `when_to_use` | триггеры активации — фразы/намерения пользователя |
| `user-invocable` | можно ли вызвать напрямую как команду |
| `keywords` | помогают находить скилл по теме |
| `argument-hint` | подсказка по аргументам для быстрого вызова |
| `category` / `metadata` | организация и версия |

`description` + `when_to_use` — самое важное: это то, по чему агент **выбирает** скилл среди
десятков других. Пиши конкретные триггеры, а не «помогает с задачами».

## Тело: интерактивный workflow

Дальше идёт пошаговый сценарий. У `task-scheduler` он такой (сокращённо):

```
Шаг 1. Дедлайн — если в тексте нет срока, спросить (AskUserQuestion).
Шаг 2. Категория + выходные/праздники — объединённый вопрос.
Шаг 3. Распределение — blocks | even.
Шаг 4. Запрос плана (асинхронно):
   - вызвать MCP-tool plan_task(...) → вернёт { jobId, status: "running" }
   - ОПРАШИВАТЬ plan_result({ jobId }) каждые ~5с, пока status != "running"
   - НЕ выдумывать план самому; показать planMd дословно, gaps как ⚠
Шаг 5. Подтверждение — спросить, создавать ли события.
Шаг 6. commit_plan(...) → показать созданные события с htmlLink.
```

Это и есть «UX-логика» скилла, которой нет ни в сервисе, ни в обёртке. Сервис умеет считать план
и создавать события; *как спросить пользователя и в каком порядке* — описано здесь.

### Вопросы пользователю

Сценарий опирается на `AskUserQuestion` (механизм OpenClaw задать пользователю выбор). Пример из
Шага 3:

```
header: "Распределение"
question: "Как раскидать подзадачи по времени?"
options:
  - "Блоками (рекомендую)"  → distribution: "blocks"
  - "Равномерно по дням"    → distribution: "even"
```

Скилл описывает вопрос и **маппинг ответа во входные параметры MCP-инструмента**.

## Защита от ошибок (важнейшая секция)

LLM-агент склонен «домысливать». Поэтому в SKILL.md явно прописывают красные линии. У
`task-scheduler`:

```
## Защита от ошибок
- НИКОГДА не вызывай commit_plan без явного подтверждения пользователя (Шаг 5).
- Если plan_task вернул unplaced[] — покажи их, не вызывай commit_plan с обрезанным planом.
- Если plan_healthz сообщает ok:false — не зови plan_task, скажи что сервис недоступен.
```

И для async (Шаг 4) — прямой запрет фантазий:

```
**Важно:** если plan_result не дошёл до done, у тебя НЕТ плана — не сочиняй слоты и не вызывай commit_plan.
```

Это не перестраховка: на практике агент **именно так и ошибался** — после таймаута тула выдумывал
план «из головы» (см. [урок 06](06-async-i-tajmauty.md)). Каждую известную грабли стоит закрывать
строкой в SKILL.md.

## Где живёт код (раздел-навигация)

В конце SKILL.md полезно дать карту: где сервис, где обёртка, где регистрация. У task-scheduler:

```
## Где живёт код
- Сервис: task-scheduler/ (LangGraph + Kimi)
- MCP: task-scheduler/mcp/ → http://task-scheduler-mcp:8080/mcp
- Регистрация: config/openclaw.json → mcp.servers.task_scheduler
```

Это помогает и человеку, и агенту в будущих сессиях.

## Чеклист хорошего SKILL.md

- [ ] `description` и `when_to_use` дают чёткие триггеры активации.
- [ ] Перечислены MCP-инструменты и порядок их вызова.
- [ ] Каждый вопрос пользователю → понятный маппинг в аргументы.
- [ ] Есть секция «Защита от ошибок» с явными «НИКОГДА/обязательно».
- [ ] Описана обработка нестандартных ответов (`unplaced`, `gaps`, `error`, `not_found`).
- [ ] Навигация по коду в конце.
